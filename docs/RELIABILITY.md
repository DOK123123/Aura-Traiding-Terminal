# Надёжность рыночных данных (этап 1)

Формулы индикаторов и поиска аналогов не изменены. Новые проверки блокируют
использование повреждённых или неподтверждённых данных, а не создают котировки.

- OHLCV должен быть конечным, цены положительными, high/low согласованными,
  объём неотрицательным. Timestamp — неотрицательное целое, выровненное по
  таймфрейму. Закрытая история не содержит будущих/незакрытых свечей.
- Окно BTC строго упорядочено и непрерывно. Идентичные дубликаты REST
  дедуплицируются, конфликтующие отклоняются. Live-события не откатывают свечи;
  регресс high/low/open/volume или пропуск требует повторной загрузки истории.
- Золото допускает календарные разрывы. Агрегируются только полные блоки
  исходных свечей. Неполный блок пропускается; цены и объёмы не дополняются.
- Свежесть истории: не более двух таймфреймов после последнего закрытия.
  Закрытый рынок золота тоже помечается как устаревший для текущего сигнала.
- BTC: события старше 15 секунд вызывают rebootstrap; backend ждёт событие
  максимум 15 секунд. Возраст события свыше 10 секунд отключает показ score.
- Браузер восстанавливает соединение после close/error или молчания:
  30 секунд после начала доставки BTC, 120 секунд при начальной загрузке
  или для золота. Повтор имеет backoff 2–15 секунд и небольшой jitter.
- При задержке/ошибке график сохраняется, но UP/DOWN скрываются, текущий
  pattern-сигнал отображается WAIT. После свежих данных показатели возвращаются.
- POST `/api/patterns/analyze` для CURRENT MARKET принимает `chart_source`:
  `Binance · Spot`, `Dukascopy · XAUUSD BID` или
  `TradingView · OANDA:XAUUSD`. При отсутствии/несовпадении сервер возвращает
  SOURCE MISMATCH и WAIT. Frontend дополнительно проверяет текущий инструмент,
  таймфрейм, источник и свежесть графика при получении результата и обновлениях.
  Исторические replay/backtest не выдаются за текущий сигнал.
- Если старый дисковый архив BTC содержит разрыв, анализ использует только
  последнюю непрерывную часть. Сами сохранённые записи не удаляются.
- Ошибки REST, upstream WebSocket, золотого резерва и pattern-запросов
  записываются в WARNING-логи с инструментом/таймфреймом, где применимо.

## Проверки

```sh
python -m pytest -q
python -m unittest tests.test_reliability -v
node tests/test_frontend_reliability.cjs
```

Новые тесты не требуют внешней сети. Node нужен только для frontend-тестов,
а не для обслуживания приложения. В ограниченной среде Codex полный pytest
может быть недоступен; это не означает, что весь существующий набор выполнен.

После Render redeploy проверить BTC 1m (500/2000), переход минутной свечи,
переключение таймфреймов, отключение/восстановление сети телефона и золото.
При отсутствии котировок должен быть понятный статус, без направленного сигнала.
При различии источников графика и архива ожидается WAIT, а не LONG/SHORT.

Торговля, API-ключи и автоматическое исполнение не добавлены. Ограничения
бесплатного Render и непостоянного диска этим этапом не устранены.
