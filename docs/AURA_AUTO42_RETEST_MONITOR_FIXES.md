Base main: `bad41f2563f38ed4659d2aa222fd66413c212a9d`.
This PR changes Paper setup bookkeeping and passive monitoring only. No merge,

## Retest / breakout correction

Previously, every breakout replaced `active`, even when its earlier setup was
still waiting. This could change the level and restart the eight-bar deadline.
On a retest candle, a later breakout in the same iteration also replaced the
level before strategy.py used it for SL.

`segment_states` now retains an unresolved setup until its existing retest,
failure or eight-bar expiry condition resolves it. New breakout/structure events
are still reported and order-block recognition is unchanged. On confirmation,
the closed candle captures `retest_origin` (direction, original level, original
breakout close). The existing `breakout_level` field used by strategy.py returns
that original level on the confirming candle, even if a new setup starts there.
The new setup can subsequently be evaluated only on later closed candles.

The 1–8-bar window, wick tolerance 0.25 ATR, confirmation/failure buffer 0.1 ATR,
directional-body requirements, EMA/ADX/MTF, liquidity/volatility/opposing-level
filters, SL 1.5 ATR and TP multiple 2 are unchanged. strategy.py and Paper Engine
are byte-identical to base. Affected setup decisions/stops can change because
they now use the intended original setup; identical historical trade results
are neither claimed nor required for a defect correction. No parameters were
optimized and no new profitability/backtest performance claim is made.

Regression coverage includes LONG/SHORT, an intervening continuation breakout,
expiry measured from the original breakout (eligible at bar 8, expired at bar 9),
cancellation followed by an opposite setup, and one retest per completed setup.
Appending changed future prices cannot rewrite earlier states; a forming bar
is rejected by the existing production analysis validator.

Two supplied historical BTCUSDT 15m CSV cases reproduce the original overwrite:

| Closed UTC | Retest | Correct original level | Incorrect old output | Original breakout close UTC |

| 2026-10-13 18:00 | SHORT | 83222.28 | 83151.01 | 2026-10-13 17:15 |

Both are recomputed on the exact closed production rolling window and still
reject with MTF_NOT_ALIGNED. They prove the level fix, not a production trade or
looser filtering. This CSV's origin is user-supplied and not independently
authenticated; it is not generated by these tests.

## Monitor correction

An engine REJECT previously populated `last_rejection`, then a following
DECISION could overwrite it in the same run or a later candle. The journal kept
the rejection, but the summary could hide the failed execution attempt.

New bounded snapshots separate:

- `execution_rejection`: original reason for the latest rejected execution
  attempt, including its run/candle/position identity. Only another engine REJECT
  replaces this historical category; subsequent checks cannot overwrite it.
- `latest_check`: latest decision, its underlying strategy reason/direction and
  its own UTC/run/candle identity, including a later successfully queued signal.
- `strategy_rejection`: latest rejected decision/check; these checks can include
  portfolio-state reasons as well as strategy filters.

`entry_rejection` remains available for old consumers and prioritizes the saved
execution failure. The owner UI labels the execution failure as historical and
shows subsequent checks separately. A successful later OPEN does not erase the
last failed attempt; the latest check and current position show current state.
The next failed attempt replaces that category with its own IDs.

Additional fields are backward-compatible JSON; no SQL migration or reset is
needed. Old snapshots without stage metadata remain explicitly stage-unknown;
no historical failure is guessed or backfilled. Original journal records and
live-verification predicates are unchanged. Monitoring cannot open/close a trade.

Offline LONG/SHORT controller regressions queue a fixture signal, cause a real
engine next-open stop rejection in temporary SQLite, then process NO_CONFIRMED_SETUP,
MTF_NOT_ALIGNED and a later queued check. The original rejection survives all
checks, duplicate tick and service restart; no position/fee is created. These
are isolated fixtures, never synthetic production signals or live evidence.
The JS regression runs the actual refresh/render code and verifies separate
reasons, run IDs and legacy rendering using textContent and GET only.

The existing isolated execution/monitor verifier was also rerun to refresh its
code-bound TEST ONLY artifact. Its trace remains WAITING_FOR_REAL_SIGNAL with
`live_cycle_verified=false`; updating the test report never promotes live status.

Validation: **1246 Python tests passed**, zero skipped, one existing Starlette/
AnyIO deprecation warning; all **17 JavaScript suites passed**. The full Python
run explicitly enabled the existing disposable PostgreSQL Practice verifier,
without changing its code or using hosted Supabase. All **12 new regression
cases passed**, all 200 Python files parsed, app.main imported, and JavaScript
syntax/diff checks passed.

## Existing historical analog compatibility

The shared SMC file is part of the shipped analog bank's strict software hash.
Leaving the old bank would make it fail closed as incompatible. The guard was
not weakened and the old metadata was not simply relabelled.

The bank was rebuilt with the existing frozen builder/protocol from 72 official
Binance Spot monthly BTCUSDT 15m ZIP/CHECKSUM pairs (2020–2025), downloaded over
verified HTTPS and checked against each official checksum. Its compact source
manifest and comparison evidence are in `AURA_AUTO42_RETEST_MONITOR_FIXES.json`.
The known missing/invalid bars were handled by the existing gap/quarantine rules,
without synthetic fills: 210280 raw, 210272 valid, 160 missing including 8
quarantined rows.

The rebuilt bank contains the same 4136 timestamps/samples. All matching fields,
vectors, signatures, normalizers and forward outcomes match base exactly; a
regression pins their pre-fix fingerprints. Only context `failed_breakout` labels
(13 indexed rows) and `retest` labels (8) differ as expected from the lifecycle
fix. Protocol, thresholds, calibrations and outcome calculations are unchanged.
The existing descriptive validation was rerun; this is no new optimization or
evidence of profitable trading. Prior research reports remain historical reports
of their own original artifact, not results silently relabelled as this rebuild.
