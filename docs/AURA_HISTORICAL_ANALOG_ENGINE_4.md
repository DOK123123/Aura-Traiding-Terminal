## Нормализация и проблема 4h

15m/1h: fit только на 2020; 4h: только на 2020–2021. В 2020 после прогрева и разрывов осталось **873** состояния 4h, меньше действующего минимума 1000. Поэтому период 4h расширен до конца 2021 **по достаточности признаков, без просмотра результатов торговли**; получено 1636 калибровочных состояний. Для 4h development-оценка начинается только в 2022. Ни validation, ни 2025 не входят в fit.

В старой Q1-2020 калибровке не было доступного 4h-контекста: mean=0/std-floor=0.1 для h4, поздние ±1 превращались в ±10 и обрезались до ±5. В 4.0 отдельная достаточная per-TF калибровка, без изменения формул/прежних отчётов. Стандартное отклонение floor=0.1, clamp ±5 сохранены. Ниже clipping по **всем feature cells новой индексной сетки после fit**, а не непосредственно сопоставимая со старой статистикой частота одного h4 признака.

|---|---:|---:|
| 15m | 90 / 56847 | 0.1583% |
| 1h | 40 / 13734 | 0.2912% |

Покомпонентные counts сохранены в JSON. Distribution shift всё ещё возможен: низкая доля clipping не доказывает достаточность калибровки.

## Similarity и причинность

Сначала exact filters: биржа/рынок/символ/TF/версия, валидный непрерывный сегмент, regime, EMA direction, HH/HL/LH/LL, structural mask, MTF mask/directions и наличие объёма. Затем RMS standardized Euclidean с равными весами семи существующих семейств: trend/structure; volatility; volume; range/levels; liquidity/SMC; momentum/pullback; MTF. Distance ≤1.5, максимум 64 соседей, минимум 20 для DESCRIPTIVE_ONLY; меньше — INSUFFICIENT_ANALOG_DATA. Это совпадение целого вектора, не близость абсолютных цен/RSI.

Все четыре исхода аналога должны завершиться строго до query. Дополнительный embargo — 250 свечей TF между историческим событием и query. Pairwise purging требует разницы >32 свечей; окна исходов не пересекаются. Ранжирование использует только признаки, исходы не участвуют в выборе. Non-overlapping count — **не эффективный независимый N**: EMA/MTF и рыночные режимы зависимы. Эффективный N и confidence interval остаются UNKNOWN/null. Это намеренное отсутствие недостоверной оценки, не mock-значения.

## Исходы и расходы

Для H=4/8/16/32: raw forward return = close[t+H]/close[t]−1, mean/median/min/p10/p90/max, частоты положительных/отрицательных/нулевых изменений; MFE/MAE по наблюдаемым high/low относительно signal close. Drawdown — консервативная **верхняя OHLC-оценка**, high-before-low внутри каждой свечи; фактическая intrabar последовательность неизвестна. Эмпирические p10/p90 — распределение, не confidence interval.

Отдельно unit-notional LONG/SHORT: вход по следующему реальному open, выход по H close; adverse slippage 0.05% на каждый fill, комиссия 0.10% на каждую сторону. Переиспользованы существующие Decimal `fill`/`fee`; вычисления precision=64, публикация процентов до 12 десятичных знаков. Это описательная time-exit гипотеза, **не стратегия со SL/TP, не portfolio PnL, не проверка возможности Spot SHORT/borrow/funding**. Риск/балансы/sizing production не затронуты. Частота роста не равна вероятности прибыльной сделки после расходов.

## Хронологическая проверка и baseline

Development 2021–2022: prequential expanding memory (для 4h только 2022). Validation 2023–2024: замороженный банк с resolved_at < 2023-01-01. Query outcomes также должны завершиться до конца своего split. Прошлые данные допустимы для прогрева; будущие — нет. Оценочная сетка фиксирована: каждый четвёртый индексный query. Сохранены годовые counts/MAE. Это развёртка по времени, не новая оптимизация.

**2020–2025 уже многократно изучались. 2025 не является blind holdout и исключён из проверки прогнозов**; его завершённые descriptive states допустимы в памяти для последующего 2026 live query. Ни один label 2025 не может попасть в validation 2023–2024. Для независимой проверки нужен новый заранее запечатанный forward-период: фиксировать hash артефакта/правила и прогноз до исхода, затем отдельно собирать закрытые свечи и считать заранее заданные ошибки. Такой forward collection в этой сессии не проводился.

Базовые прогнозы среднего raw return: unconditional, same-regime, simple-trend из той же причинно допустимой индексной сетки; random matched-count со seed 20261014+query timestamp. Расходы не превращают raw-return forecast MAE в net PnL; эти показатели отделены.

## Артефакт и reproducibility

В git включён только компактный `app/intelligence/data/analogs-v4.json.gz`, не исходный ZIP/CSV. Manifest включает source archive SHA, quality summary, отдельные per-TF normalizers, полный frozen protocol, feature version и SHA256 фактических зависимостей: parser/importer, feature/detector/aggregation, normalization, Decimal helpers, builder и live adapter. Canonical JSON + gzip mtime=0. Проверяются compressed/uncompressed limits, структура/версии, целостность, software hashes, порядок/UTC, завершённость исходов, timestamps подтверждений. Повреждённый/отсутствующий/несовместимый файл означает ANALOG_DATA_UNAVAILABLE, **без fallback к 1.0**.

Размер: **1794717 bytes** gzip, 8950558 bytes JSON. SHA256 gzip: `e4db02f80f47d8b5071af987957106e0d560a5bf77d32db9af3cfde50ba9e82d`. Content SHA256: `690ae11432d571bdcf4aac2b25950ec619b81e376ce3b1a58f25341cb6efac5c`.

Жёсткие runtime limits: 2 MiB gzip, 16 MiB распакованного JSON, 8192 states, 64 результата. Файл читается один раз при startup; история не скачивается и не рассчитывается на HTTP запросе. Lookup выполняется вместе с анализом в существующем CPU worker, результат использует общий кэш/single-flight 3.2; неизменные свечи не пересчитываются. Существующие 12s fetch/8s cooperative compute/22s snapshot/24s browser budgets не менялись. Реальное принудительное CPU termination не добавлено.

Сборка с локальным архивом (никаких API-ключей и сетевых запросов):

```sh
python scripts/build_historical_analogs.py /path/AURA_BTCUSDT_15m_2020-2025.zip \
  --output /tmp/aura-analogs/analogs-v4.json.gz \
  --report /tmp/aura-analogs/report.json
```

Повтор той же команды использует checkpoint только при совпадении protocol/software/archive hash. Офлайн runner ограничен существующими importer limits (211000 свечей), хранит states только в пределах этого архива; не предназначен для Render web-процесса. Изменённая программа не переиспользует несовместимый checkpoint. Если исходный архив отсутствует, CLI сохраняет BLOCKED_DATA_REQUIRED.

Порядок установки артефакта: проверить report и SHA; скопировать gzip по фиксированному пути `app/intelligence/data/analogs-v4.json.gz`, включить в проверяемый commit, затем обычный согласованный деплой. В этом commit совместимый файл уже включён. При изменении fingerprinted исходников сначала пересобрать артефакт; несовпадение не обходить. Автоматический deploy API не вызывался, фактический Render deploy не проверялся. UI показывает cutoff данных артефакта отдельно от времени его успешной загрузки сервером и свежести текущих свечей.
