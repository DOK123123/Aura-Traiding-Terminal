# Веб-развёртывание Aura Trading Terminal

Проект предназначен для Python-хостинга с постоянно работающим процессом,
HTTPS и поддержкой WebSocket. Статический хостинг для него не подходит.
Рекомендуемый первый вариант — Web Service на Render или аналогичный
Python-сервис на Railway. Развёртывание ещё не выполнено.

## Настройки сервиса

- Рабочая директория: корень проекта (где находятся `app/` и `static/`).
- Python: 3.12; минимально допустимая версия приложения — 3.11.
- Команда установки: `python -m pip install -r requirements.txt`.
- Команда запуска: `python start_web.py`.
- Проверка состояния: `/api/health`.
- Адрес процесса: `0.0.0.0`; порт: переменная окружения `PORT`, иначе 8000.
- Один процесс Uvicorn: кеш, блокировки и ограничения вычислений локальны процессу.
- HTTPS и маршрутизацию к порту процесса предоставляет хостинг.

Эквивалентная команда для хостинга с POSIX shell:

```sh
python -m uvicorn app.main:app --host 0.0.0.0 --port "${PORT:-8000}" --workers 1
```

Frontend использует относительные `/api/...`, `/static/...` и `/ws/market`:
backend и интерфейс нужно размещать на одном домене в корне сайта.
WebSocket автоматически использует `wss` при HTTPS.

## Файлы

Обязательны: `app/` со всеми модулями, `static/` со всеми ресурсами и
`static/vendor/` с библиотекой и лицензиями, `requirements.txt`, `start_web.py`.
Сохраните `Procfile` и `.python-version`, если платформа их поддерживает.
На ветке Research Lab `scripts/`, `research/` и необходимые файлы `docs/`
являются runtime-зависимостями: не исключайте их из сборки. `app.main` через
Research Lab импортирует существующие исследовательские модули и читает
зафиксированные протоколы при старте. Сохраните полный Git checkout, включая
`docs/*PROTOCOL.json`, `docs/data/`, отчёты и журналы `docs/LAB_V2/` и
`docs/AI_RESEARCH_V1/`. Удаление всех JSON/отчётов может сломать запуск или
исследовательские API. `tests/` и `README.md` для обслуживания страницы не нужны. `start.bat` предназначен только для локальной Windows.

Не переносите `.venv/`, `__pycache__/`, `.pytest_cache/`, `.git/`, `.env`,
локальные логи и временные результаты. Версионированные исследовательские
артефакты из `docs/` сохраняйте. Секреты задаются настройками хостинга.
`pytest` в requirements нужен для проверок; его наличие не мешает запуску.
Сторонние импорты приложения покрыты requirements, остальное — стандартная
библиотека Python. Версии зависимостей в этой проверке не устанавливались.

## Данные и ограничения

Сервису необходим исходящий HTTPS/WebSocket-доступ к Binance, Dukascopy и
TradingView. Регион хостинга и ограничения источников могут влиять на котировки;
работоспособность данных нужно проверить после размещения отдельно от health.
Резерв TradingView использует неофициальный протокол.

Приложение пишет кеш и SQLite-архив в `.cache/` в корне проекта. Эта папка
должна быть доступна для записи. Для сохранения накопленной истории при
перезапусках нужен постоянный диск, смонтированный в `.cache/`. Без него
интерфейс работает, но архив и кеш могут теряться при пересоздании сервиса.
Выберите постоянно работающий экземпляр, если нужны непрерывные live-обновления;
засыпающий тариф прерывает WebSocket и требует повторного подключения.

После размещения проверить главную страницу, static, REST обоих инструментов,
WebSocket и pattern API. Только затем можно подтвердить полную работоспособность.

## Условия Research Lab перед размещением

Сначала выполните план из `docs/AI_RESEARCH_INTEGRATION_AUDIT.md`. Аудит не
разрешает deploy: обнаружены блокирующее сохранение полного Volatility Breakout
отчёта и неподтверждённый запас ресурсов для совместного backtest с Auto Paper.
Никаких новых SQL/RPC в production Supabase не требуется.

История Research Lab находится в `.data/ai-research/ai-research-v1.sqlite3`, а не
в `.cache/` и не в Supabase. Она сохраняется только если этот точный каталог
лежит на постоянном диске. Без него после пересоздания сервиса история теряется.
Платный LLM не нужен; оставьте `AURA_RESEARCH_LLM_ENABLED=false`. Не меняйте
существующие trading/scheduler переменные, баланс и позиции ради лаборатории.
