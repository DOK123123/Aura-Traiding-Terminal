# Aura Trader 5.0 — AURA ANALYST v1

Изолированный аналитический помощник для **ручной** проверки BTCUSDT Bitget
USDT-M Futures. Не открывает ордеры/виртуальные сделки, не читает счёт, не включает
и не выключает Active43. Новых зависимостей, ключей, БД или платных сервисов нет.
Работа выполнена в существующей ветке feature/aura-trader-5-manual-analyst / PR #58.

## Где открыть

Главная страница → ссылка **AURA ANALYST · перейти к сценарию ↓** над настройками
графика. Панель находится после графика/Market Analysis, перед модулями.
Публичный GET `/api/analyst` не требует торговых ключей/owner cookie, потому что
возвращает только публичный рыночный анализ; account/control API не вызывает.
Кнопка «Обновить анализ» и обновление раз в минуту при видимой вкладке — только GET.
На сервере нет нового scheduler, таймера исследований или фонового торгового цикла.

## Реальные данные и изоляция

Используется существующий строгий public-only Bitget Client, но **новый отдельный
экземпляр**, собственные lock/cache/cooldown. Он создаётся лениво при первом
аналитическом GET: ошибка аналитического клиента не блокирует старт Auto Paper.
Закрытие аналитики не пропускает cleanup существующего контроллера даже при ошибке.
Ни Service/Store Active43, ни Paper/Practice/реальные API-ключи не используются.
Вызовы public client: server time, публичный USDT-M perpetual contract и история
BTCUSDT. Только GET `api.bitget.com`, fixed symbol/product; никакого Spot/fallback.

На каждый интервал 5m/15m/1h/4h загружаются 200 закрытых непрерывных свечей. Проверяются
OHLCV, timestamp UTC, окончание последней свечи, exchange/request freshness и
совпадение источника; 4h — native Bitget 4H, не неподтверждённая агрегация.
Граница закрытия подтверждается временем самой биржи, а не только часами
сервера: при расхождении границ локального/Bitget времени результат WAIT.
Все интервалы ограничены одним as-of; пересечение новой границы 5m во время
загрузки даёт WAIT. Пропуски/будущие/повторные/устаревшие свечи отклоняются.

На успешный refresh обычно 5–6 public GET (time, contract по TTL, четыре history).
Максимум один refresh in-flight на процесс, cache 30 секунд, общий timeout 35 секунд,
собственные bounded retries/semaphore публичного клиента. 429 включает cooldown;
устаревший успешный план не подставляется при ошибке. Аналитика не берёт trading lock.
Кеш хранит только компактные показатели/план в памяти; сохранения в Supabase нет.

LIVE-график остаётся существующим. Его текущая свеча и визуальные EMA могут
меняться внутри интервала. Карточки AURA ANALYST рассчитываются отдельно,
**только по закрытым свечам**; live-price не передаётся в расчёт сценария.
Главный график по-прежнему имеет 1m/5m/15m/1h; анализ 4h доступен в карточке контекста.

## Формулы и правила сценариев

EMA20/50: seed SMA первого периода и стандартная рекурсия. RSI14: Wilder average
gain/loss; flat=50, односторонний рост/падение=100/0. ATR14: Wilder, первые 14 TR
с предыдущим close, то есть минимум 15 candles. Этот ATR-контракт принадлежит
помощнику; формулы существующей стратегии/индикаторов терминала не изменены.

Фибоначчи: экстремумы прошлых 60 закрытых 15m свечей **перед последней**. Для LONG
low должен предшествовать high, для SHORT — наоборот. Это trailing-range reference,
а не обещание значимого swing/pivot; будущая pivot-подтверждающая свеча не используется.
Уровни 23.6/38.2/50/61.8/78.6 доступны в раскрываемом блоке.

Ручной LONG/SHORT выдаётся только при всех условиях:
1. EMA20–EMA50 по модулю >0.1 ATR, одинаковое направление 5m/15m/1h.
2. 4h не противоречит направлению (NEUTRAL допускается как контекст).
3. RSI **5m** в 52–68 для LONG либо 32–48 для SHORT. Старшие RSI только показываются.
4. Есть пересечение зоны Fibonacci38.2–61.8 с EMA20(5m) ±0.5 ATR.
5. Последний closed close не дальше0.25 ATR от этой зоны; последняя свеча
   направленная и продолжает движение относительно предыдущего close минимум0.05 ATR.
6. SL за структурой последних трёх 5m свечей и минимум1.5 ATR за зоной;
   TP ограничен прошлым экстремумом 15m и 2.5R.
7. R/R по худшему входу зоны после модели расходов >=1.5.

Цена зоны/SL/TP округляется к **публичному Bitget contract price tick**: зона внутрь,
stop наружу, target к входу; R/R пересчитывается после округления. Нет fallback
к угаданному tick при отсутствии contract metadata. Это план, не валидированный
exchange order: размер/маржа/плечо/lot/min-notional/ваш аккаунт не читаются.

Модель расходов фиксированная и явно показана: fee10bps и adverse slippage5bps
на сторону; fee считается от цен после slippage. Funding/реальный bid-ask/ваш
VIP tier не включены. `risk_plan` — чистая гипотетическая оценка, не позиция или
изменение средств. Панель не показывает рассчитанный размер заказа или баланс.

Если условие не выполнено — WAIT с конкретной причиной, без entry/SL/TP.
Это прозрачная начальная эвристика, **не подтверждённое торговое преимущество**.
R/R — геометрия модели, не вероятность выигрыша. Не проводилась оптимизация или
подгонка условий под текущий рынок. Закрытые свечи могут уточняться источником;
следующий снимок изменит анализ, история прибыльных сигналов здесь не имитируется.

## Время жизни и браузер

План действует не более60 секунд и не переходит через следующую границу5m.
Любое истечение/ошибка/неполный контракт ответа → WAIT и очищенные уровни.
При сворачивании запрос отменяется, старый ответ больше не может заменить новый;
при возвращении и bfcache pageshow выполняется новый read-only refresh.
Автоторговля не зависит от этого браузерного таймера и здесь не контролируется.
Физический Android Chrome и production deployment нового API не проверены.

## Исправления исходного PR и проверки

В исходном PR были только pure primitives и 6 тестов. Исправлены проверки
integer period/bool/NaN/положительной OHLC и риск-оценка: теперь adverse fills
включены до расчёта комиссии, учитывается fee/slippage cross-term. Это не правка
финансового execution engine, а отдельная planning-функция PR #58.

Добавлены unit/reference tests RSI/EMA/Wilder ATR/Fibonacci/costs; LONG/SHORT/WAIT,
context conflict, closed-candle invariants, native public-protocol adapter, ошибки,
таймаут/429/clock freshness, snapshot expiry, cache, authorization-free GET-only
контракт без store/controls, frontend late-response/bfcache/expiry/XSS guards.
Полный regression, результаты публичной проверки и screenshots: `RESULTS.json`.

Скриншоты `*-synthetic.png` — настоящая отрисовка HTML/JS в Chromium с явно
помеченными тестовыми свечами, не рыночный результат. `*-public-snapshot.png` —
локальная отрисовка сохранённого публичного снимка Bitget с исходным as-of, не
production-сервис и не доказательство торговли. В обоих случаях нет сделок.

## Повторение локально

```bash
python -m pytest -q
node --test tests/*.cjs
python -m scripts.verify_aura_analyst_browser --output-dir /new/path/browser
```

Для явной локальной проверки реального public API без аккаунта:

```python
import asyncio
from app.aura_trader5_service import AnalystService
async def check():
    service = AnalystService()
    try:
        result = await service.inspect()
        print(result['state'], result['reasons'], result['frames'])
    finally:
        await service.close()
asyncio.run(check())
```
