# Issue #73: повторный аудит мобильной навигации

Дата: 2026-11-02. Основа: `099f0a73e8ec6c21ed33950a718c65f2ff16f696`.
Четыре вкладки уже реализованы в PR #74; этот патч сохраняет их и исправляет
ошибки, найденные повторной проверкой. Новая версия и новая инфраструктура не
создаются. Аудит выполнен отдельными проходами логики/UX и безопасности;
внешний независимый рецензент не привлекался.

## Находки и исправления

- **Высокая, целостность отображения:** Главная проверяла возраст Bid/Ask только
  после ответа API. Зависший запрос оставлял старые LIVE/WATCH и цену на экране
  без ограничения времени. Теперь независимый секундный таймер повторно
  проверяет сохранённый ответ исходными правилами свежести: котировка старше
  5 секунд скрывается, статус становится STALE. Данные не синтезируются.
- **Средняя, жизненный цикл:** `pagehide` навсегда выключал опрос; восстановления
  при `pageshow` не было. Теперь скрытие останавливает запросы и очищает модель,
  возврат запускает новый опрос. Идентификатор сессии и запроса не позволяет
  опоздавшему ответу или ошибке перерисовать новую сессию.
- **Средняя, ресурсы:** перекрывающиеся запросы не имели timeout. Одновременно
  разрешён один GET с отменой через 8 секунд. Таймер проверки свежести работает
  независимо от сети. Таймеры и запросы освобождаются при остановке.
- **Низкая, защитная валидация:** нечисловое время браузера теперь явно даёт
  STALE, вместо обхода сравнений с NaN.

## Проверка сохранения функций

Карта переноса DOM остаётся в `NAVIGATION_RU.md`. Главная, Сигналы, График,
Ещё, Back/Forward, тема и существующие панели не заменяются копиями. Signal
Confidence, редактируемые Entry/SL/TP/net RR, журнал, график, аналитика и ручная
виртуальная форма остаются прежними. Проверки цены/источника/спреда, порог
50–100, запрет ложного CONFIRMED и статус NO_EDGE_FOUND не ослаблены.

## Проход безопасности

Изменён только презентационный монитор Главной: фиксированный owner-protected
same-origin GET `/api/preview/signals/snapshot`, без новых endpoints, аккаунтов,
secrets, SQL, режима PAPER/Active43 или торговых POST. Ошибки сети не выводятся
как raw exception. DOM заполняется через textContent; HTML-инъекции нет.
По исправленному коду нерешённых critical/high находок не обнаружено.

## Воспроизводимые проверки

- `node tests/test_issue73_navigation.cjs`: 9 тестов, включая зависший transport,
  timeout/abort, запрет параллельных запросов, опоздавший ответ, suspend/resume,
  HTTP/JSON ошибки, восстановление и недопустимые часы.
- `node --check static/aura-mobile-shell.js` и
  `node --check scripts/verify_issue73_browser.cjs`.
- В существующий Chromium journey добавлены зависание API при видимом LIVE,
  скрытие просроченной цены и восстановление после pagehide/pageshow на desktop,
  Pixel 7 и 360px Android touch viewport. Проверяются ноль POST и page errors.
- Перед merge обязательны полный Regression CI с изолированным PostgreSQL и
  Manual Preview Browser на точном SHA патча. Фактические run/deploy результаты
  фиксируются в PR после завершения; предыдущие CI за новый прогон не считаются.
- Отдельный job `isolated-preview-health` делает только GET публичного health
  указанного Preview: проверяет scope, работающий observer и выключенные
  execution/Active43/scheduler. Redirects запрещены; ответ ограничен размером,
  попытки и timeout ограничены. Job повторно запускается после deploy. Это
  отдельная hosted-проверка, не часть offline market/browser доказательств.

Локальный Chromium runtime ограничен окружением (setsockopt EPERM), поэтому
браузерная проверка выполняется существующим GitHub workflow. Браузерные данные
в workflow — fixtures, не подтверждение actual hosted Bitget LIVE или физического
Samsung. Ручные или реальные сделки в проверках не выполняются.
