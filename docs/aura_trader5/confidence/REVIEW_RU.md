# Issue #70 — отдельные проходы code/security/hidden-error review

Проверен diff новой ветки относительно `feature/aura-live-manual-trader5`,
путь public Bitget → закрытые свечи → техническая оценка → owner preview →
ручная форма и отдельный исследовательский журнал.

Аудит выполнен отдельными проходами того же разработчика, а не независимой
третьей стороной. Внешняя аттестация **не заявляется**.

## Подтверждённые дефекты, исправленные до PR

1. **HIGH correctness, `app/hunter/store.py`, `Store.observe`:** первоначальный
   расчёт баллов записывался только при новом watermark. Через пять секунд
   новая Bid/Ask-котировка теряла пару к записанному score; гипотезы исчезали
   до следующей свечи. Исправлено обновлением только quote-priced score метаданных
   при каждом успешном цикле, при этом входной snapshot остаётся неизменным.
   Проверяется повторным наблюдением одного cutoff с новой котировкой.
2. **HIGH research reproducibility, `app/hunter/confidence.py`, `score_at`:**
   расширенная историческая серия EMA200 имела другой seed, чем LIVE-окно
   ровно 260 свечей. Исправлено вычислением всех влияющих на score EMA/RSI/ATR/MACD
   на фиксированном causal 260-bar prefix. Тест сравнивает replay-индекс,
   отдельный 260-bar LIVE-prefix и изменённое только будущее.
3. **MEDIUM notification, `static/signal-confidence.js`:** запись звукового
   статуса в общий localStorage-журнал могла потеряться при конкурентном
   сохранении другой вкладки. Добавлен отдельный ограниченный список id
   уведомлений под Web Locks, recheck свежести внутри lock, default OFF и
   необходимость явного действия владельца.
4. **MEDIUM completeness, `app/hunter/store.py`:** изначально score-журнал
   хранил только UNKNOWN. Добавлен отдельный forward outcome журнал с
   модельным PnL и явными `OPEN/UNKNOWN/gap`, без записи счетов/ордеров;
   `CONFIRMED` и существующий eligibility registry не менялись.
5. **HIGH isolation, `static/signal-confidence.js`:** первоначальный ручной
   перенос заполнял поля существующей виртуальной PAPER-панели. Для Issue #70
   он отделён в собственные локальные поля и явное копирование текста для
   Bybit Demo с повторной проверкой свежести перед обоими действиями.
   Взаимодействие с PAPER/Active43 отсутствует.
6. **MEDIUM result attribution, `LocalJournal.outcomes`:** обновлённая
   котировка внутри той же закрытой свечи давала тот же id, но forward-результат
   сервера относился к цене первого обнаружения. Теперь исход связывается
   с точными `input_sha256` и временем исходной Bid/Ask; при несовпадении
   локальный журнал оставляет UNKNOWN вместо ложного исхода.
7. **HIGH issue acceptance, manual Entry/SL/TP edits:** при правке уровней
   первоначально отображалась лишь исходная server net R/R. Добавлен отдельный
   причинный пересчёт по `AURA5_EXIT_QUOTE_COSTS_2` с комиссией 10 bps/сторону,
   проскальзыванием 5 bps/сторону и funding-резервом, проверки геометрии и
   minimum net R/R 1.5, а также явное подтверждение перед копированием текста.
   JavaScript/Python численная паритетность зафиксирована в Node unit test.

## Security review

- Новый frontend использует только owner-protected GET `/api/preview/signals/snapshot`;
  все динамические строки вставляются через `textContent`.
- Устанавливаются только независимые локальные `sc-manual-*`; существующие
  `mp-*` и кнопки виртуального счёта не затрагиваются. Никаких торговых POST,
  биржевых команд, секретов, account clients, API-ключей и автоматического
  исполнения в новых модулях нет.
- Скоринговые записи имеют `UNVALIDATED`, `probability_tp_before_sl=null`,
  `exchange_execution=false` и отдельно version/hash/source/cutoff. Старые,
  чужие, неоднозначные или stale данные не включают WATCH/перенос.
- Реестр `app/hunter/eligibility.json` остаётся пустым. Нет изменений
  main/production/PAPER/Active43/тарифов/Render environment.
- Пропавшие или повреждённые необязательные score-метаданные не приводят
  к ложному сигналу или отключению основной статистики.

## Residual risks / NOT PROVEN

- Реальная вероятность выигрыша и статистическое преимущество не установлены;
  нет virgin holdout, исторического Bid/Ask и подтверждённого реального PnL.
- Фоновый звук на засыпающем Render Free и физическая слышимость не доказаны.
- Исследовательские планы иногда содержат произвольную цель 2.5R: это
  фиксированная гипотеза для проверки, не математический прогноз.
- PostgreSQL/Chromium в локальном контейнере отличаются от hosted CI; перед
  интеграцией обязателен точный CI head и desktop/mobile Browser PASS.

Решение об интеграции принимается только после PASS обоих workflows, отсутствия
critical/high в итоговом diff и подтверждения target branch/Render service.
