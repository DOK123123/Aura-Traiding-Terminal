# Aura 5.0: единый терминал с серверными сигналами

Владелец 30 октября 2026 отменил создание отдельной 6.0 и разрешил переделать существующую 5.0 и выполнить deploy. Используется прежний сервис `srv-dbh1vljl550s738f4t30` и прежний URL. Новый сервис, тариф, диск, аккаунт или пароль не создаются. Production Aura 4.3 и main не изменяются.

## Изменение

При `AURA_PREVIEW_SIGNALS_ENABLED=true` существующий `app.manual_preview.main:app` запускает public-only наблюдатель шести семейств. На странице 5.0 старая клиентская панель заменяется серверными карточками, журналом и звуком. График, replay и ручная форма остаются в том же интерфейсе. Существующий владелец `aura` и его preview-пароль защищают все новые API/static через прежний middleware. Новый пароль не нужен.

- Ровно 260 закрытых native свечей на TF 5m/15m/1h/4h; forming-bar исключается. Исследовательский engine и его правила не оптимизировались.
- GET `/api/preview/signals/snapshot` и `/api/preview/signals/inputs` читают только выделенный журнал публичных наблюдений. Они не читают/изменяют виртуальный кошелёк или аккаунт Bitget.
- Каждый цикл сохраняет точные входы, model/contract/hash и исходы в отдельной SQLite. Существующая Supabase DB/ledger и SQL не меняются.
- Технические LONG/SHORT остаются исследовательскими UNVALIDATED. Их Entry/SL/TP можно перенести в форму только после нового GET и повторной проверки свежести; POST/ордер при этом не отправляется. BUY/SELL по-прежнему требуют отдельного подтверждения и прежних server guards.
- Звук автоматически воспроизводится только для CONFIRMED/VALIDATED, с gesture, mute и постоянной дедупликацией. Поставляемый реестр интеграции пуст; UNVALIDATED молчит. Кнопка проверки звука остаётся доступна явно.
- Отключение связи, неверные источник/время/стопы, истечение срока или скрытая вкладка убирают активные планы/линии. Состояние worker и частичные сбои TF видны явно.
- Цикл, котировки и диагностические counters копируются до передачи snapshot в thread, чтобы старт/обновление не смешивали старые котировки с новым числом циклов.
- Неполадка необязательного наблюдателя не останавливает существующий терминал/защитный virtual worker. Все фоновые задачи отменяются и borrowed HTTP client закрывается его существующим владельцем.

## Ограничение текущего бесплатного размещения

Журнал наблюдателя — `work/manual-preview-signals.sqlite`, локальный ephemeral Render filesystem. Он может исчезнуть при restart/redeploy; это прямо указано в интерфейсе/API. Сбор прекращается во время сна бесплатного сервиса. Это не гарантированный 24/7 forward. Виртуальный счёт хранится отдельно прежним способом. Платный диск/план автоматически не подключались; keep-alive/cron не добавлялись.

Положительное независимое преимущество после расходов не найдено. NO_EDGE_FOUND остаётся результатом исследований. Технический сценарий не является гарантией прибыльной сделки.

## Воспроизводимость старых исследований

Исходное исследование strategy_improvement фиксировало хеши старых main.py/page.py как доказательство изоляции. Их новые версии нужны для явно разрешённой интеграции. Старые файлы сохранены побайтно в `research/strategy_improvement/baseline_runtime/`, исходный protected-files.json и сохранённые результаты не менялись.

`baseline.cjs` проверяет одновременно старые архивы и точные хеши разрешённых новых runtime-файлов из runtime-integration.json. Неизменённые Replay/Analyzer/формулы по-прежнему проверяются на текущих путях. Исследовательский manifest использует именно прежние хеши, а полный offline regeneration должен совпадать с сохранёнными результатами. Отдельные тесты доказывают отказ при порче старого архива, нового runtime или вычислительного baseline. Это не замена старых хешей новыми ради PASS.

Отдельный code/security review: parse(scope/password/project) остаётся до любых клиентов; новый env ключ ограничен AURA_PREVIEW_ и boolean true/false. Новые маршруты защищены прежним owner middleware, POST запрещён, размер export ограничен. PublicMarket имеет фиксированный Bitget GET allowlist/таймауты/без redirects. В UI входные данные выводятся через textContent; поле формы заполняется только после свежего GET, без исполнения. Аккаунты/секреты не экспортируются, настройки manual/Active43/PAPER не меняются. В этом проходе открытых critical/high замечаний не обнаружено.

## Deploy

После PASS точного CI source head переносится fast-forward в существующую ветку `feature/aura-live-manual-trader5` (с проверкой ожидаемого старого SHA). В Render только существующего Preview добавляется `AURA_PREVIEW_SIGNALS_ENABLED=true`, с merge env и сохранением остальных ключей. autoDeploy остаётся OFF; выполняется один ручной deploy. Команда запуска не меняется. Проверяются точный deployed SHA, LIVE, публичный health с signal_observer_enabled/running и безопасный стартовый лог `PREVIEW_SIGNALS_PROBE` с полученными TF. Лог не содержит credentials или приватных HTTP-ответов. Защищённый hosted UI может потребовать отдельный вход владельца; браузерный отказ входа не обходится.
