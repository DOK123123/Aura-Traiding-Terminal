# AURA 5.0 · Historical Replay и звуковые уведомления

Новая работа вынесена в `feature/aura-replay-alerts`: PR #62 уже слит владельцем, его последний head `cacbfe11a54445a4ddb13e8cbcd933b8ddd31581`. База этой работы — проверенный актуальный main `8d7de160d6b6eb099ace6c9292220762c3250413`. Merge/deploy в этой задаче не выполнялись.

## Что добавлено

- Отдельная раскрывающаяся панель **«Проверка стратегий · Historical Replay»**, независимый исторический график. LIVE и Bid/Ask не останавливаются и не заменяются историей.
- Источник: официальный публичный Bitget history-candles либо явно выбранный сохранённый реальный архив Bitget из репозитория (1 июля — 29 октября 2026 UTC, правая граница исключена). Автоматической подмены API архивом нет.
- Выбор дат UTC, 15m/1h/4h, до 6000 свечей периода + 200 свечей прогрева. История проверяется на полный период, UTC, OHLCV, разрывы, дубликаты и противоречия; пропуски не заполняются.
- ×1 (одна свеча в секунду), ×10, ×50, ×100, максимально быстро с ограничением вычислительного пакета 8 мс и возвратом управления event loop. Старт, пауза, следующая свеча, следующий сигнал, сброс; автоматическая пауза при каждом допустимом LONG/SHORT. При скрытии вкладки Replay ставится на паузу.
- Entry/SL/TP, net R/R, стратегия, время, причины/отмена, отдельные линии на историческом графике. Журнал найденных и отклонённых сценариев; в интерфейсе последние 100, в JSON/CSV — весь обработанный период. CSV экранирует формулы.
- Уведомления LIVE: мастер-переключатель, отдельные LONG/SHORT, громкость Web Audio, активация нажатием, тест звука, настройки после перезагрузки. LONG — 660→880 Гц, SHORT — 440→330 Гц. Выключение/скрытие закрывает AudioContext, чтобы старый звук не возобновлялся позже.
- Дедупликация сохраняется **до звука**: версия стратегии + стратегия + направление + TF + канонический ID/время; старые watermarks не проигрываются заново. При недоступном хранилище автоматический звук блокируется. После обновления страницы требуется повторная активация звука нажатием; включённый переключатель сам по себе не обходит ограничения браузера.

## Причинность и общий движок

Replay вызывает те же `AuraManualStrategies.evaluate` и `atQuote`, что LIVE. Пороги и условия трёх стратегий не изменены. `atQuote` — вынесенные без ослабления прежние проверки текущего входа, зоны, геометрии и расходов; описание costs теперь соответствует рассчитанному net R/R.

Каждый шаг получает только последние 200 уже закрытых свечей на момент закрытия текущего бара. Следующий open, будущие high/low, будущие подтверждения swing и результаты не передаются. На графике видна только обработанная история. В тестах изменение всех будущих OHLCV не меняет прошлые решения; отдельный тест сравнивает Replay с LIVE на одинаковом закрытом префиксе и модельной котировке.

Исторические Bid/Ask отсутствуют. Модель: bid/ask от последнего известного close ±1 б.п. (полный спред 2 б.п.), комиссия 10 б.п. и adverse slippage 5 б.п. на сторону. Это **не настоящие исторические котировки и не проверенный персональный тариф**. Funding отсутствует. Replay показывает технические сценарии, не исполняет сделки и не считает прибыльность: `statistical_result=NOT_EVALUATED`, `UNVALIDATED / NO_VALIDATED_EDGE`. Ранее полученные отрицательные результаты статистического исследования этим не отменяются.

## Безопасность и ревью

- Исторический маршрут только в отдельном `app.manual_preview.main`, за существующей owner-аутентификацией. Фиксированный HTTPS-хост/GET endpoint, никаких пользовательских URL, ключей биржи, редиректов или account API.
- Один одновременный исторический запрос на экземпляр; максимум 34 страницы, 200 строк/страницу, 200 КБ на ответ, общий таймаут 60 с, ограниченный размер периода. 429 при занятости, 400 при неверном запросе, 503 при недостоверном/неполном ответе. Нет бесконечной очереди или ретраев.
- Replay не публикует LIVE-события, не заполняет торговую форму и не имеет order-функций. Звук получает только результат LIVE-движка и не связан с командами счёта. Replay всегда немой.
- Звук запрещён для WAIT/REJECTED/STALE, неполных полей, неверной геометрии/ID, просроченных и повторных сигналов; UNVALIDATED явно поясняется. При выключенном звуке/направлении новые отметки запоминаются, чтобы потом не проиграть накопленные сигналы.
- Серверные Decimal-риск, owner/CSRF, идемпотентность и ручное подтверждение не менялись. Production, PAPER, Active43, SQL и реальные торговые настройки не изменялись.
- Отдельные code/security review: прослежены public history → integrity → causal prefix → общий движок → отдельный график; LIVE results → durable dedup → user-armed Web Audio. Credentials не добавлены; динамический текст — textContent, исключая неизменяемую статическую разметку панелей. Нерешённых critical/high находок в изменениях не обнаружено.

## Куда нажимать после разрешённого развёртывания

1. Открой изолированную Aura и войди как владелец.
2. Раскрой **«Проверка стратегий · открыть Historical Replay»**.
3. Оставь сохранённые реальные свечи Bitget, даты **1–29 октября 2026**, TF **15m**. Нажми **«Загрузить период»**.
4. Нажми **«Следующий сигнал»** — ускоренный поиск остановится на LONG/SHORT, покажет план и линии. Нажимай снова для следующего события. Для обычного воспроизведения выбери скорость и **«Старт»**. **«Сброс»** возвращает к началу, **«Пауза»** останавливает расчёт.
5. Для API-истории выбери **«Загрузить из Bitget API»**, доступные даты и снова **«Загрузить период»**. Ошибка/неполный период не заменяется синтетикой.
6. В блоке **«Уведомления · LIVE»** включи звук, оставь LONG/SHORT, выставь громкость, нажми **«Проверить звук»**. После перезагрузки/возврата из сна нажми **«Активировать звук»**. Отключение — снять **«Включить звук»**.

## Фоновые push: рекомендация, без внедрения

Для закрытой вкладки нужен отдельный серверный public-market observer, сохраняющий дедупликацию/очередь уведомлений, защищённая регистрация Web Push-подписок, VAPID-ключ только на сервере и Service Worker с Push API/Notifications API. Подписка — исключительно после явного согласия пользователя, с отзывом и удалением endpoint. Событие должно содержать время, срок действия, технический/статистический статус; просроченные сигналы нельзя выдавать за актуальные. Нужна работающая во время сна страницы серверная среда; спящий Render Free не гарантирует своевременность. ОС управляет звуком push, режим «Не беспокоить» и блокировка могут мешать. Ни Service Worker/push-подписки, ни платные сервисы, ни новый worker в этой задаче не создавались.
