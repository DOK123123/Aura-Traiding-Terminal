# Aura Trader 5.0 · этап 2 — manual workspace

Ветка `feature/aura-trader-5-manual-analyst`, Draft PR #58. База main b721a0c.
Разработка и тесты локально. Нет merge, deploy, SQL, настройки или вызовов
production, изменения PAPER/Active43, сделок или торговых ключей.

## Что работает

1. Основной существующий график Bitget Futures / Lightweight Charts 5.0.8
   сохранён. Над ним — «Ручные инструменты · без ордеров»:
   горизонтальный уровень (одно касание), trend line / зона S/R / Fibonacci
   (две точки). `Выбрать` → объект → перетаскивание круглых маркеров.
   Escape отменяет незавершённое рисование/перетаскивание. Удаление только выбранной
   локальной аннотации, не торговых данных. Touch и мышь используют Pointer Events.
2. Числовой редактор Entry / SL / TP / направления / учебного BTC-количества.
   «Нанести / обновить» сохраняет план; после выбора можно двигать уровни.
   «Взять свежий сценарий ANALYST» только заполняет поля, не создаёт заявку.
   Прозрачная служебная серия расширяет autoscale до пользовательских SL/TP.
   Ни аннотации, ни формирующаяся свеча не поступают в серверную аналитику.
3. Каждый из 5m / 15m / 1h / 4h показывает MACD 12/26/9, объём и его отношение
   к **предыдущим** 20 свечам, последние подтверждённые swing high/low,
   структуру HH_HL / LH_LL / RANGE / UNCONFIRMED и RSI-дивергенции.
   MACD EMA — SMA seed; signal EMA9 начинается после первого валидного MACD.
4. Pivot radius=2: на свече i экстремум строгий относительно двух соседей
   слева и справа. Он виден только после **закрытия i+2**, `confirmed_at=time_i+3*step`.
   Плоские равные экстремумы не объявляются pivot. RSI у pivot использует только
   его префикс; дивергенция подтверждается после второго pivot, не задним числом.
   Сравниваются последние однотипные pivots: расстояние ≤50, второй не старше
   10 свечей. Это свечной контекст, не доказательство order flow или ликвидности.
5. В ANALYST — совпадения/противоречия EMA, MACD, структуры и дивергенций,
   относительно LONG/SHORT сценария либо тренда 1h при WAIT. Объём не имеет
   выдуманной направленности. Эти дополнительные поля **контекстные**, не новая
   оптимизация и не замена фиксированным правилам сценария этапа 1.
   Показаны отмена по TTL, неполным/устаревшим данным, потере EMA alignment
   и закрытию 5m за ориентиром SL. Устаревший сценарий скрывается.
6. «Журнал ручных сценариев» ниже ANALYST. Сохраняет план, направление,
   timeframe, UTC, заметку; отдельно пользователь может ввести **гипотетическую**
   цену выхода и оценить исход. Это не OPEN/CLOSE, нет позиций, баланса,
   биржевого исполнения, автоматического мониторинга или статистики доходности.
   Повторный идентичный план не дублируется; оценённый исход не переписывается.
   Доступен экспорт JSON, не импорт и не синхронизация с аккаунтами.

## Изоляция, хранение и расходы

- Серверный `/api/analyst` остаётся GET-only и не получает аннотации/журнал.
  Нет новых серверных write API, БД, схем, cookie, secret или auth scopes.
- Аннотации: `aura.manual.drawings.v1`, отдельно по timeframe, BTCUSDT Futures;
  максимум 40 объектов на frame, 192 KiB JSON.
- Журнал: `aura.manual.scenarios.v1`, максимум 200 записей, 256 KiB JSON.
  Хранение — localStorage этого origin/браузера. В приватном режиме, после очистки
  сайта и при смене origin данные могут исчезнуть. Экспортируйте резервную копию.
  Это НЕ постоянный облачный owner-журнал и НЕ защищённое хранение секретов.
- Запись журнала под Web Locks (HTTPS/localhost). Отсутствие Web Locks,
  повреждённые/слишком большие данные или ошибка localStorage запрещают запись.
  Предыдущее содержимое не удаляется/не заменяется пустым. При изменении в другой
  вкладке запись блокируется до reload; exclusive lock + сверка текущего снимка
  предотвращает потерю записей при конкурентном сохранении.
  Для аннотаций нет межвкладочной транзакции: редактировать их в одной вкладке.
- Учебные ограничения ручного плана: условные 10 000 USDT, loss при SL после
  расходов ≤50 USDT, entry notional после slip ≤2000 USDT. Это не чтение/сброс
  существующего счёта и не изменение его risk guards. План не валидирует
  доступную маржу/лот/лимиты реального аккаунта Bitget.
- Расчёт гипотетического исхода — BigInt fixed-point 1e-8: entry/exit против
  направления на 0,05%, taker fee 0,10% от фактического моделируемого номинала
  каждой стороны. Цены adverse округляются в неблагоприятную сторону; расходы
  округляются вверх, signed PnL к нулю с точностью 1e-8 USDT. Проскальзывание уже
  включено в PnL, повторно не вычитается. Комиссия консервативная модель, не
  установленный тариф пользователя Bitget. Funding и отдельный spread не учтены.
- Нулевая инфраструктурная стоимость: нет новых сервисов и runtime-зависимостей.
  Сетевых запросов по сравнению с этапом 1 не добавлено. Фиксированные 200 свечей
  на timeframe; новые вычисления ограничены этой историей и не backtest в API.
- DOM использует textContent, а не HTML из заметок/ответов. Read-only анализ
  публичен, журнал не передаётся серверу, экспорт содержит пользовательские
  заметки: не публикуйте его без проверки на личную информацию.

## Проверка

```bash
python -m pytest -q
node --test tests/*.cjs
python -m scripts.verify_aura_analyst_browser --workspace --output-dir /new/path
```

Новые Python tests — независимый Decimal reference MACD, линейный/плоский ряд,
подтверждение pivots с задержкой, LONG/SHORT RSI-divergence, volume baseline,
causality и запрет future candles. JS — знаки/fees/slip и известные LONG/SHORT
суммы, риск, перезапуск localStorage, дедупликация, corruption/limits, эксклюзивная
запись и отказ stale tab, геометрия/ручки Fibonacci, закрытый контекст, изоляция.

Реальный Chromium загружает текущие HTML/JS и настоящий vendored LWC. В offline
стенде воспроизводимо проверяются: все четыре инструмента кликами, перемещение
ручки, нанесение плана, сохранение/оценка исхода, отсутствие дубля, reload,
desktop/mobile layout и отсутствие API writes. Скриншоты синтетические и явно
помечены; это не сделки, не публичные цены, не production-проверка.

Подробные результаты: `STAGE2_RESULTS.json` и `screenshots/stage2/`.
Физическое устройство Android и целевой Render не проверялись; существующие
отдельные regression suites LIVE WebSocket/REST запускаются без их изменения.

## Остаточные ограничения и следующий шаг

- Нет доказанного преимущества, калиброванной вероятности или рекомендации сделки.
- Журнал — локальный ручной notebook, результаты субъективные, не верификация fills.
- Ручная разметка не создаёт подтверждённые уровни/сигналы и может включать будущую
  область графика. Аналитика использует только проверенные закрытые свечи сервера.
- Нет cross-device sync, server backup/восстановления аннотаций, импорта журналов.
- Проекты с одноимёнными именами перечислены в `UPSTREAM_REVIEW_RU.md`, нет
  заимствований их реализации, юридическая совместимость не предполагается.
- Следующий самостоятельный этап: отдельный offline runner по описанному контракту
  и replay fixtures, затем review. Интеграция/publish только с отдельным разрешением.
