# Historical Trade Outcome Analyzer · отчёт

Данные: сохранённые реальные свечи Bitget BTCUSDT USDT-M (`research/strategy_engine/bitget-2026-07-10-15m.json.gz`), 2026-07-01 — 2026-10-29, конец не включая. API-загрузка и лимит 6000 + 200 прогрева не изменены. SHA входов и результатов находятся в `summary.json`; подробные гипотезы, расходы, исходы, месяцы и кривые — в `*-base.json.gz` / `*-stress2.json.gz`.

## Методика

- Тот же `evaluate` / `atQuote`, без изменения фильтров. Свечной префикс заканчивается на момент решения. Анализ исходов получает новую свечу для прежних сигналов, затем регистрирует только что обнаруженные сигналы. Свеча сигнала никогда не исполняет этот сигнал.
- Условный вход по касанию reference Entry только следующей свечой (срок совпадает с valid_until); это модель, не гарантия исполнения лимитного/рыночного ордера и не воспроизведение дискреционных действий пользователя. Для LONG касание модельного ask, для SHORT bid. При marketable open — плановый Entry без выгодного улучшения цены. Далее неблагоприятное проскальзывание. Гэп за SL до подтверждённого входа: UNKNOWN без исполнения.
- Выход LONG по модельному bid, SHORT по ask. Гэп за SL: фактический модельный open и неблагоприятное проскальзывание; гэп за TP: без выгодного улучшения, на TP. Оба уровня в свече: SL_FIRST, ambiguous=true. На свече входа, если вход внутри диапазона и TP без SL, порядок Entry/TP неизвестен: UNKNOWN, никакой прибыли. Entry/SL внутри свечи: консервативный SL с отметкой неоднозначности.
- Удержание не более 96 свечей с включением свечи входа. Затем TIMEOUT с выходом по close. Нет касания Entry: TIMEOUT без исполнения и без PnL. Конец выбранных данных до достоверного завершения: UNKNOWN. До конца Replay незавершённые PENDING/OPEN не имеют PnL. При экспорте явно complete=false. Нет скрытого чтения свечей после выбранного периода.
- Полный спред 2 bps, проскальзывание 5 bps/сторону, комиссия 10 bps/сторону. Сдвиг bid/ask от OHLC ±половина спреда. В stress2 всё это удвоено, сигналы сохранены неизменными. Funding, очередь, ликвидность и реальный исторический Bid/Ask не известны и не моделируются. Формула USDT: sign × (exit_fill − entry_fill) − fee × (entry_fill + exit_fill), фиксированная гипотеза 1 BTC. JS Number, исследовательская точность, не денежный счёт.
- R = net PnL / abs(плановый Entry − SL). Win Rate — доля положительных net исходов среди определённых закрытых (TP/SL/исполненный TIMEOUT); UNKNOWN и TIMEOUT без входа исключены. PF = сумма положительных PnL / abs(сумма отрицательных); без убытков PF не определён, не Infinity. Средняя прибыль/убыток по знаку net PnL.
- PnL и кривые — сумма независимых гипотез 1 BTC, по каждой стратегии и стороне отдельно. Это НЕ капитал/доходность портфеля; есть пересекающиеся позиции, модель экспозиции и сложный процент отсутствуют. Просадка — падение от пика этой суммы закрытых результатов, USDT и R, без mark-to-market. При одинаковом времени выхода используется стабильный порядок ключа сигнала. Время исполнения известно лишь с точностью до свечи; экспорт хранит начало соответствующей свечи.
- Месяц UTC — когорта времени возникновения сигнала; исход может закрыться позже. Частичный Replay маркируется явно. Расчёт до конца идёт последовательными короткими пакетами, без автопаузы; обычный Старт и Следующий сигнал сохраняют автопаузу.

## Периоды и ограничения доказательств

5–31 августа (UTC, до 1 сентября), сентябрь и 1–28 октября (до 29 октября). Август начинается 5 числа для полного прогрева 200 свечей 4h из архива с 1 июля. Каждый период загружается отдельно, конец периода цензурирует открытые исходы. Это описательный анализ уже известных данных, НЕ независимая контрольная выборка. Параметры не оптимизировались по результатам. `UNVALIDATED / NO_VALIDATED_EDGE`, статистическое подтверждение отсутствует; малые группы — INSUFFICIENT_EVIDENCE. Нулевые группы S/R показаны явно.

```bash
PYTHON=python node scripts/analyze_replay_outcomes.cjs work/trade-outcomes
node --test tests/test_trade_outcomes.cjs tests/test_replay_alerts.cjs
PYTHON=python node scripts/verify_replay_alerts_browser.cjs work/replay-alerts-browser
```

Сравнить result_sha256 в summary.json. Экспорт JSON включает полный журнал, параметры, группы, месяцы и кривые. CSV содержит типы MODEL, TRADE, STATISTICS, MONTH, CURVE: метаданные в отдельной колонке JSON, числовые поля в строках сделок; CSV-инъекции экранируются. Старый экспорт Replay сохранён, JSON теперь также содержит outcomes.

## Проверка и безопасность

Проверки покрывают реальные архивные данные, причинность (изменение всех будущих OHLCV не меняет прежние решения и исходы), повторный расчёт, оба направления, no-fill, stop/target gaps, неоднозначные свечи, комиссии, сроки и отсутствие знаменателей. Браузерный сценарий дополнен полным расчётом, сравнением UI JSON с чистой моделью, CSV, выбором кривой и отсутствием горизонтального переполнения Android. Актуальные результаты CI и SHA публикуются в Draft PR #63 после завершения прогонов. Локальная установка Chromium неуспешна: загрузчик получил некорректный zip; локальный UI запуск не заявляется PASS.

Отдельный code/security review: поток OHLC → causal prefix/shared rules → аналитический ledger → textContent/canvas/export. Нет запросов записи, аккаунтных импортов, ключей или новых зависимостей. Owner-защита статических ресурсов сохранена. Счёт виртуальных сделок, LIVE и звук не связаны с аналитическим ledger. Новые пользовательские значения не вставляются в HTML. Критических/high замечаний в просмотренном diff не осталось.

## Использование после отдельно разрешённого deploy

Проверка стратегий → выбрать период → Загрузить период → Рассчитать исходы до конца → Результаты проверки. Для пошагового просмотра остаются Старт / Пауза / Следующая свеча / Следующий сигнал / Сброс. Для исходов использовать Результаты JSON / Результаты CSV. Таблицы прокручиваются внутри панели касанием; кривая переключается по стратегии и LONG/SHORT. При сворачивании вкладки расчёт приостанавливается.

В этой задаче deploy не выполняется; production, main, PAPER, Active43 и SQL не меняются. Физический Android и реальная слышимость звука не проверены. Даже положительный отдельный месяц не доказывает устойчивую эффективность.
