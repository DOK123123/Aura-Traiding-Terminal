# AURA 5.0 · три независимых закрытых стратегии

## Вердикт

Технические сценарии LONG и SHORT обнаружены на сохранённых реальных свечах Bitget. Преимущество не подтверждено: все три стратегии UNVALIDATED / INSUFFICIENT_EVIDENCE, NO_VALIDATED_EDGE. Две стратегии с модельными сделками показали отрицательную expectancy. Разворотная стратегия дала два технических сетапа, оба отвергнуты расходами. Пороги после просмотра результатов не изменялись.

## Метод

Источник: публичные Bitget BTCUSDT USDT-M 15m, 2026-07-01 00:00 — 2026-10-29 00:00 UTC (правая граница исключена), 11 520 непрерывных свечей. Из них агрегированы 2880 1h и 720 4h. Прогрев 200 закрытых свечей отдельно по каждому TF. Сохранённый архив и его SHA-256 указаны в JSON. Это те же данные, что уже изучались в PR: контроль 2026-10-01 — 2026-10-29 повторно использован, **не независимая OOS-выборка**. Июль–сентябрь — development; независимая историческая проверка недоступна. Нужен новый forward-период.

Правила и критерии квалификации зафиксированы в research/manual_strategies/protocol.json до этого прогона. Никакой оптимизации. Радиус swing = 2, только уже подтверждённые пивоты. Breakout использует уровень, подтверждённый ДО пробоя. Новая формирующаяся свеча исключена из подтверждений. Тест инвариантности меняет её OHLCV без изменения решений.

Вход — следующий open внутри зоны, повторная проверка геометрии и net R/R ≥1.5. Одна гипотетическая позиция на strategy/TF, горизонт 16 свечей, stop-first при SL/TP в одной свече, неблагоприятные гэпы стопа; касание TP ограничено целевой ценой. Development-позиции, чей полный горизонт пересекает границу контроля, исключены. Незавершённые хвостовые позиции исключены, их сетапы остаются REJECTED в журнале.

Комиссия 0.10% на сторону, проскальзывание 0.05% на сторону, модельный полный спред 0.02%. Это допущения, не фактический тариф/исторический Bid/Ask. Funding, глубина и реальная внутрисвечная последовательность недоступны. Разрешение касаний — OHLC выбранного TF с консервативным stop-first; минутный путь не заявляется. Результаты не доказывают фактическую исполнимость.

Доходности: без плеча, 1x номинал, последовательное компаундирование внутри strategy/TF. Это исследовательская модель, не исполнение ограничений Manual Paper (2000 USDT / 0.5% риск). Сводные Win Rate/PF/expectancy по нескольким TF описывают объединение сделок; pooled DD/return намеренно null, потому что одновременные сделки не образуют определённого портфеля. Для DD/return используйте строки конкретного TF.

## Стресс расходов

replay-stress15.json.gz и replay-stress2.json.gz содержат два разных измерения: (1) полный повторный запуск с более строгим фильтром затрат; (2) fixed_sample_stress — те же сделки базового прогона, переоценённые с ×1.5/×2 расходами без отбора новой выборки. Для оценки чувствительности используйте второе. Положительного преимущества в контроле не получено.

## Forward observer

Реальный ограниченный захват публичных REST + WebSocket с фактическим временем получения: forward-report.json и forward-capture.json.gz. 254 LIVE-события, 184 сообщения котировок, 0 обнаруженных технических сетапов, 0 ордеров. Короткое наблюдение не позволяет оценить прибыльность. Это проверка из среды разработки, не из Render.

В интерфейсе observer сохраняет Bid/Ask, время обнаружения, Entry/SL/TP, причины, отмену, статус и гипотетический исход с расходами. Никаких запросов ордеров. Вход в гипотетическую модель — только на первом фактическом наблюдении свежего сценария. Выход LONG по bid, SHORT по ask. Пропуск >10 с, потеря котировки или сон вкладки дают UNOBSERVED без выдуманного PnL. Восстановление localStorage не отправляет запросы; отклонённые/просроченные записи без fill. Последние 500 наблюдений; выгрузка JSON. Это локальный браузерный журнал: работает только пока открыта вкладка, не круглосуточный серверный сборщик и не Supabase-хранилище.

## Интерфейс и границы

Preview получает три независимых стратегии, LONG/SHORT/WAIT/REJECTED, статистический статус отдельно, причины, отмену, свежесть, расходы, зону входа и net R/R. Линии выбранного TF рисуются только для свежего допустимого сценария и удаляются при STALE. Кнопка переноса заново проверяет свежесть и заполняет только Entry/SL/TP. Размер пользователь задаёт сам; BUY/SELL подтверждаются отдельно. Серверные owner/CSRF, Decimal-риск, идемпотентность, ограничения и защита остаются прежними. Старые профили — отдельный предварительный аналитик, новые три стратегии не требуют их согласия.
