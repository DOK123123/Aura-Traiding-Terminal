## Стоимость

Для этого SQLite backend базовый вариант:

| Позиция | USD/месяц |
| --- | ---: |
| Web service `0.5c-512mb` (legacy Starter), 512 MB | 7.00 |
| Persistent disk 1 GB по 0.25 USD/GB | 0.25 |
| Базовый итог | **7.25** |

Это стоимость одного постоянно работающего экземпляра при 1 GB диска, до налогов, конвертации/комиссий карты, дополнительных подписок и превышения включённых ресурсов. Увеличение диска увеличивает сумму: `7 + 0.25 × GB`. Отдельный платный workspace Pro для этой конфигурации не требуется. Фактическую сумму подтвердить в Render перед сохранением платных изменений; размер диска выбрать 1 GB, если он доступен в форме. Не покупать отдельный PostgreSQL, worker или биржевую подписку для v1.

Почему нужен paid compute: Free засыпает и не поддерживает disk. Защитные виртуальные SL/TP должны проверяться сервером, когда телефон/браузер закрыт. Постоянный диск сохраняет SQLite при перезапуске/deploy. Платный сервер не устраняет сбои Bitget, ошибки БД и перерывы deploy.

Источники, проверенные 26.10.2026: [Pricing](https://render.com/pricing), [Compute plans](https://render.com/docs/compute-plans), [Persistent disks](https://render.com/docs/disks), [Deploys](https://render.com/docs/deploys), [Environment variables](https://render.com/docs/configure-environment-variables).

2. Войти в Render и посмотреть вкладку Environment. Не публиковать скриншоты со значениями секретов и не присылать пароль в чат.
3. Сверить таблицу переменных ниже. Пока не менять compute и не нажимать Add disk: обе операции из Dashboard могут автоматически запустить deploy даже при Auto-Deploy Off.
4. Решить, подходит ли бюджет 7.25 USD/месяц. Подтверждение бюджета не является разрешением на открытие виртуальной позиции.
5. Перед любым будущим deploy/restart прочитать owner status Active43 и убедиться, что выпуск не повлияет на существующую активную торговлю/позицию. В рамках этой подготовки Active43 не останавливается и не переключается.

В логах текущего сервиса обнаружены `HISTORY_CANDLE_CHANGED` и отдельные `RATE_LIMIT` в Active43. Это отдельная проблема существующего автоматического контура. По этим логам нельзя объявить его текущий счёт OFF или подтвердить отсутствие позиций. Такой проверки до выпуска пока нет; нельзя оплачивать/перезапускать сервис, считая Active43 гарантированно выключенным.

## Настройки для будущего согласованного выпуска

Менять только после отдельного разрешения на платные действия и production deploy.

| Где | Требуемое значение/действие |
| --- | --- |
| Compute | `0.5c-512mb` / Starter, один экземпляр |
| Disks | Выделенный persistent disk, mount `/var/data`, первоначально 1 GB |
| Auto-Deploy | Оставить Off |
| Ветка и build/start | Сохранить существующие настройки; выпускать проверенный конкретный SHA |
| Health check path | Рекомендуется `/api/health`; изменение применяется только в согласованное окно выпуска |
| `AURA_MANUAL_PAPER_ENABLED` | `true` только для согласованного запуска ручного модуля |
| `AURA_MANUAL_PAPER_STORAGE` | `persistent-disk` |
| `AURA_MANUAL_PAPER_MOUNT` | `/var/data` |
| `AURA_MANUAL_PAPER_DB` | `/var/data/manual-paper.sqlite3` |
| `AURA_TESTNET_VIEW_PASSWORD` | Существующий owner-пароль, минимум 12 символов; не менять без необходимости |
| `AURA_ACTIVE43_*`, scheduler, Supabase и биржевые секреты | Не изменять, не переносить в Manual Paper |
| PAPER/START в интерфейсе Active43 | Не нажимать |

Путь `/tmp`, `.data`, каталог исходников и просто созданная папка `/var/data` не заменяют смонтированный диск. Код проверяет mount и принадлежность пути перед каждым подключением SQLite. При потере mount возвращается ошибка; новая временная база не создаётся.

## Порядок будущего выпуска

1. Получить отдельное разрешение на платный compute + disk и на deploy. Уточнить целевой SHA: после любых изменений PR старый зелёный CI не подтверждает новый commit.
2. Зафиксировать live SHA, прочитать owner status Active43, позиции и режим без изменений. Если Active43 ON/автоматически восстанавливается либо есть позиция/неизвестный исход — остановить процедуру выпуска до отдельного решения пользователя. Не переключать его самостоятельно.
3. Убедиться в сохранении Auto-Deploy Off. **Не сливать PR автоматически.** Выбор последующего merge или Deploy a specific commit — отдельный согласованный шаг; Dashboard позволяет deploy конкретного SHA из связанного репозитория.
4. В Environment добавить/проверить только четыре Manual Paper переменные. Для предварительного сохранения выбирать **Save only**, а не Save and deploy. Существующие переменные сохранить. Не менять пароль или ключи.
5. В согласованное окно перейти на paid compute и добавить disk. Эти действия могут сами перезапустить старый код: до них должна быть выполнена проверка Active43 и получено разрешение на перезапуск. Mount доступен только в runtime; не создавать/мигрировать базу в Build или Pre-deploy Command.
6. Развернуть ровно согласованный проверенный SHA. Не выбирать Deploy latest commit, пока рабочая ветка сервиса — main без Manual Paper. Дождаться статуса **Live**, сверить SHA, не считать принятый deploy завершённым.
7. В Shell запустить безопасную проверку из нового кода:

```bash
python -m scripts.manual_paper_preflight
```

Команда делает только публичные GET Bitget, проверку конфигурации и чтение существующего журнала через SQLite `mode=ro`. Она не создаёт баланс, не открывает/закрывает позиции и не вызывает Active43. Секреты не выводятся. Требуется `launch_ready: true`; при существующей базе также `journal_read_verified: true`. Для новой базы допустим `READY_EMPTY_DATABASE_NOT_INITIALIZED`. `write_permission_verified` проверяет права; фактическое подтверждение записи делается следующим авторизованным чтением пустого счёта, а не этой командой.

8. Открыть `/api/health`: HTTP 200. Проверить статическую страницу и отсутствие новых ошибок Manual Paper в логах.
9. Выполнить проверку с телефона ниже — **без сделок**.
10. После согласованного перезапуска того же сервиса сравнить состояние пустого Manual Paper: баланс/версия/позиция/история должны сохраниться. Не удалять базу для исправления ошибки. Если `CORRUPT_JOURNAL` или `PERSISTENT_DISK_REQUIRED`, оставить торговлю заблокированной и разбирать причину.

При disk-backed deploy будет перерыв обслуживания всего веб-сервиса; поэтому процедуру нельзя выполнять, обещая, что существующий Active43 вообще не заметит restart. Его код и настройки не меняются, а операционное влияние deploy требует отдельного решения.

## Проверка с телефона без production-сделок

1. На Samsung/Android открыть Chrome и `https://aura-traiding-terminal.onrender.com/` после подтверждённого Live нужного SHA. При старом интерфейсе обновить страницу, закрыть/открыть вкладку.
2. Найти **Manual Paper · ручной виртуальный счёт · 10 000 USDT**. Это отдельная панель от Aura 4.3/Active43.
3. Нажать «Войти как владелец». В системном запросе браузера имя — `aura`, пароль — существующий owner-пароль Render. Не вводить биржевые ключи.
4. Развернуть Manual Paper. У нового счёта ожидаются баланс `10000`, реализованный PnL `0`, нет позиции, пустая история, сообщение «Постоянный диск · баланс сохранён».
5. Убедиться, что bid/ask BTCUSDT обновляются с timestamp. При ошибке/устаревании новые операции должны быть недоступны. Если данные не свежие, **ничего не открывать**.
6. Повернуть экран, проверить читаемость полей, кнопок и журнала. Значения SL/TP и объём можно осмотреть; LONG, SHORT, «Закрыть позицию» и кнопки Active43 не нажимать.
7. Обновить страницу и повторно открыть панель: баланс/пустая позиция/история сохраняются. Закрыть и открыть Chrome — результат тот же.
8. При проверке потери связи временно отключить интернет на телефоне: после истечения 5 секунд текущая котировка/equity/PnL не должны считаться свежими, операции блокируются. Вернуть интернет и нажать «Обновить».
9. Сравнить тот же счёт после отдельно согласованного server restart. Это проверка постоянного хранения без открытия позиции.

Тест LONG/SHORT, комиссии, SL/TP, потеря ответа и реальные остановки Uvicorn выполнены на изолированной локальной базе. Production-сделка для этой проверки не требуется. Любая будущая пробная виртуальная сделка требует отдельного разрешения.

## Ограничения и критерий решения

Подготовка кода и зелёный CI не равны запуску production. До выпуска остаются: просмотр env, подтверждение оплаты, read-only owner-проверка текущего Active43, реальный mount, точный ticker из Render и визуальная приёмка телефона. Свежие закрытые свечи Bitget из Render уже подтверждены публичным `/api/market`: 500 свечей 1m, `stale=false`, последнее закрытие на 28 секунд раньше ответа (26.10.2026 13:30 МСК). Это не доказательство свежести нового ticker-адаптера: он выполняет отдельные проверки bid/ask ≤5 секунд.
