# Manual Paper v1 — отдельный виртуальный счёт

Рекомендуемый вариант для обучения: **Render Free + Supabase Free**, без платного диска. Баланс 10 000 USDT, одна ручная LONG/SHORT-позиция BTCUSDT USDT-M Futures. Код реализован в PR #57; он не сливается и не развёртывается автоматически.

## Изоляция и исполнение

- Manual Paper не использует состояние/настройки Active43. Нет реальных биржевых ордеров, пополнений, переводов или биржевых API-ключей.
- Owner Basic Auth: `aura` и существующий `AURA_TESTNET_VIEW_PASSWORD` (≥12 символов). POST требуют same-origin и `X-Aura-Paper: local-only`.
- Клиент передаёт сторону, BTC-объём, SL/TP и request ID. Клиентская execution price и чужой рынок запрещены.
- Сервер получает публичное время и ticker Bitget BTCUSDT USDT-FUTURES. Только фиксированные HTTPS GET, redirects запрещены, таймаут и размер ответа ограничены. Bid/ask, символ, часы, timestamp и спред проверяются; котировка ≤5 секунд.
- LONG входит по ask/выходит по bid; SHORT входит по bid/выходит по ask. Это модель виртуального исполнения по лучшей цене.
- Decimal-комиссия 0,06% на сторону; максимум 2000 USDT, одна позиция; риск до SL с обеими комиссиями ≤0,5% баланса. При балансе ≤9000 новые входы запрещены.
- Закрытие привязано к ID позиции. Повтор запроса возвращает исходную квитанцию, даже если цена изменилась или рынок недоступен. Численно равные входные числа нормализуются для fingerprint.

## Постоянное хранение без платного диска

`app/manual_paper/supabase_store.py` использует только выделенные RPC:

- `aura_manual_paper_v1_load`: чтение, без создания счёта;
- `aura_manual_paper_v1_lookup`: постоянная квитанция по ID/намерению;
- `aura_manual_paper_v1_commit`: короткая транзакция с singleton-lock, проверкой версии, проверкой возраста котировки по часам БД после ожидания lock, атомарной записью счёта и квитанции.

Таблицы: `aura_manual_paper_v1_account` и `aura_manual_paper_v1_requests`. SQL: [manual_paper_schema.sql](../scripts/manual_paper_schema.sql). Схема подготовлена к отдельному согласованному применению, не запускается приложением. RLS включён, `anon`/`authenticated` не имеют доступа к таблицам/RPC. Функции SECURITY INVOKER, роль `service_role` доступна только серверу. На requests запрещены UPDATE/DELETE.

Снимок содержит баланс, позицию и историю; SHA-256 проверяет целостность. Сервер проверяет математику комиссий и баланса. Версия предотвращает гонки между процессами, а повтор с неизвестным результатом восстанавливается по тому же ID. При timeout нельзя создавать новый request ID. При ошибке БД нет SQLite/memory fallback и автоматического сброса.

Для экономии бесплатного трафика одинаковая версия счёта возвращает только метаданные; полная история повторно не скачивается каждые 5 секунд. Payload ограничен 1 MiB; новый вход блокируется заранее с запасом 8 KiB для безопасного закрытия текущей позиции. Журнал/квитанции не удаляются автоматически; большой архив потребует отдельного расширения/архивирования.

Переменные для будущего согласованного запуска:

```text
AURA_MANUAL_PAPER_ENABLED=true
AURA_MANUAL_PAPER_STORAGE=supabase
AURA_MANUAL_PAPER_SUPABASE_URL=https://<project-ref>.supabase.co
AURA_MANUAL_PAPER_SUPABASE_SERVICE_KEY=<server-only service_role JWT or secret key>
```

Пароль владельца сохраняется в `AURA_TESTNET_VIEW_PASSWORD`. Ключ не публиковать в браузере, репозитории, чате или скриншоте. Значения Active43 не используются как неявный fallback. Существующий проект можно использовать с отдельными таблицами; новый платный проект не требуется.

## Ограничения бесплатного режима

На 26.10.2026 Supabase Free включает 500 MB базы и 5 GB egress; проект может приостанавливаться после недели неактивности. Read-only проверка существующей Aura показала размер базы 17,42 MB; Manual Paper таблиц ещё нет. Это не обещание неизменной квоты: другие функции Aura используют тот же проект. Контролировать фактический usage.

Render Free засыпает после 15 минут без входящих запросов и может перезапускаться. Баланс в Supabase сохраняется независимо от сна Render. **Пока сервер спит или БД/Bitget недоступны, SL/TP не проверяются.** Открытая вкладка делает обычные запросы во время использования; отдельного keep-alive, cron или платного worker не добавлено. Работа 24/7 не обещается.

SL/TP проверяются по наблюдаемому bid/ask работающим сервером примерно каждые 5 секунд плюс время HTTP/БД. Выход после gap записывается по фактической наблюдаемой цене; убыток может превысить расчётный риск. Промежуточные касания во время простоя не восстанавливаются. Funding, глубина стакана, очередь и реальная ликвидация не моделируются.

Источники: [Supabase Pricing](https://supabase.com/pricing), [Render Free](https://render.com/docs/free), проверено 26.10.2026.

## SQLite как дополнительный backend

Существующие режимы сохранены: `development` с абсолютным путём `manual-paper.sqlite3` вне Render; `persistent-disk` с проверенным mount и путём внутри него. Для SQLite на Render по-прежнему нужен платный диск; это **не требуется для Supabase backend**. Проверка mount выполняется перед каждым подключением. Автоматического переноса уже существующего SQLite-счёта нет; если он уже использовался, сначала нужна отдельная согласованная миграция с проверкой баланса, позиции и receipts. В этом проекте production Manual Paper ещё не запускался.

## API и UI

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/manual-paper/capabilities` | Публичный контракт без баланса; не доказывает readiness |
| GET | `/api/manual-paper/state?offset=0&limit=50` | Owner-чтение; первая авторизованная загрузка создаёт пустой счёт |
| GET | `/api/manual-paper/quote` | Owner-чтение свежей серверной котировки |
| POST | `/api/manual-paper/orders` | Виртуальный вход |
| POST | `/api/manual-paper/positions/{position_id}/close` | Виртуальный выход конкретной позиции |

Вход (цены демонстрационные):

```json
{"request_id":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","side":"LONG","quantity":"0.01","stop":"79500","target":"81000"}
```

Закрытие: `{"request_id":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"}`. Числа — строки, до 12 десятичных знаков; NaN/Infinity/bool/экспоненты/лишние поля запрещены. Мобильная панель показывает источник хранения, баланс, net PnL, SL/TP, статус защиты и журнал. При неизвестном результате браузер сохраняет намерение до отправки и повторяет тот же ID после reload.
