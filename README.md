# Trading Terminal

Локальный аналитический MVP для **XAUUSD** и **BTCUSDT**. Python 3.11+ / FastAPI, обычные HTML/CSS/JavaScript, TradingView Lightweight Charts 5.0.8. Node.js и сборка frontend для запуска не нужны. Приложение не отправляет торговые заявки.

## Запуск на Windows (PowerShell)

Установите Python 3.11 или новее с python.org с компонентом Python Launcher (`py`). Откройте PowerShell в папке проекта:

```powershell
cd "$env:USERPROFILE\Documents\ChatGPT\Trading Terminal"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Остановка — `Ctrl+C`. После первого создания окружения можно запускать двойным щелчком по `start.bat`. Активировать окружение и менять ExecutionPolicy не нужно. После обновления проекта повторите `pip install -r requirements.txt`: fallback использует дополнительную библиотеку `websockets`.

Если `py` не найден, используйте `python -m venv .venv` или полный путь к установленному `python.exe`. При занятом порте укажите `--port 8001` и откройте соответствующий адрес. Для разработки добавьте `--reload`.

Библиотека графика сохранена в `static/vendor/` вместе с лицензией Apache-2.0 и NOTICE; CDN при открытии страницы не требуется. Интернет нужен для установки Python-зависимостей и загрузки рыночных данных. API-ключи не нужны.

- Два инструмента, интервалы 1m / 5m / 15m / 1h, окно ровно 500 или 2000 свечей. REST возвращает закрытые свечи; live-окно включает формирующуюся свечу.

- Места для Fibonacci, divergences, funding rate, multi-timeframe analysis и Elliott Wave обозначены как запланированные, расчётов в них пока нет.

## Данные и ограничения

**BTCUSDT:** [Binance public market data](https://developers.binance.com/en/docs/products/spot/rest-api), `https://data-api.binance.vision/api/v3/klines`. Запросы разбиты на страницы максимум по 1000 записей. Объём — BTC. Региональные ограничения или ограничения частоты источника отображаются как ошибка, а не как синтетические данные.

**XAUUSD, основной источник:** [Dukascopy historical data](https://www.dukascopy.com/swiss/english/marketwatch/historical/), публичные BI5-архивы `https://datafeed.dukascopy.com/datafeed/XAUUSD/`. Реальные BID-котировки spot gold конкретного провайдера. Минутные файлы используются для 1m/5m/15m; часовые архивы — для 1h. В URL месяцы нумеруются с нуля, цены XAUUSD хранятся в тысячных USD. Архивы могут задерживаться, возможны HTTP 429/503 и перерывы рынка.

**XAUUSD, автоматический fallback:** [OANDA:XAUUSD на TradingView](https://www.tradingview.com/symbols/XAUUSD/?exchange=OANDA). Получение через анонимную WebSocket-сессию публичного графика `wss://data.tradingview.com/socket.io/websocket`; логин, ключи и пользовательские cookies не используются. Это брокерские OTC-котировки золота OANDA, не фьючерсы GC и не токены PAXG/XAUT. Запрашиваются count+1 свечей, в REST незавершённая свеча отбрасывается, в live-режиме сохраняется с отметкой предварительной. Имя и биржа инструмента проверяются по ответу разрешения символа. Общий [лимит истории публичного графика](https://www.tradingview.com/support/solutions/43000480679-historical-intraday-data-bars-and-limits-explained/) — около 5000 внутридневных свечей, однако доступ анонимной сессии может отличаться. Этот протокол **не является официально поддерживаемым публичным API**: его формат, доступные символы и ограничения могут измениться. Бесплатность текущего доступа не гарантирует SLA или права на публичную ретрансляцию данных; приложение предназначено для локального анализа.

История всегда берётся целиком из одного источника: свечи разных брокеров не склеиваются. Котировки и сессии Dukascopy и OANDA могут отличаться. Неизвестный объём сохраняется как `null` и отображается как «—», а не как нулевой торговый объём. Доступный объём/активность провайдера не является централизованным объёмом всего рынка золота.

При первоначальной загрузке цена соответствует последней закрытой свече. После подключения потока **«Последняя цена» — close последней полученной свечи, включая формирующуюся**, а не отдельный bid/ask. Текущая свеча обозначена как предварительная. История золота старше четырёх дней отвергается, включая случай долгих праздников. Никакие свечи для пропущенных интервалов не создаются. Нет mock/demo-режима или подмены инструмента. При обрыве потока показанные значения замораживаются с явным сообщением об ошибке и автоматическим повтором.

API-ответы кэшируются в памяти на 30 секунд (ключ: инструмент, таймфрейм, число свечей), загруженные BI5 — в `.cache/dukascopy/` на 5 минут. Кэш можно удалить при остановленном приложении. Доступно только локально по умолчанию. Публичный доступ, авторизация, база данных и автоторговля не входят в MVP.

При HTTP 429/503 Dukascopy выполняется один повтор с короткой задержкой (Retry-After до 5 секунд, иначе повтор пропускается). На основной источник отводится максимум 25 секунд. При сетевых ошибках, таймаутах, повреждённых данных, неполной или слишком старой истории автоматически включается резервный источник (до 45 секунд). После сбоя Dukascopy не опрашивается повторно 120 секунд или дольше, если его Retry-After требует более долгого ожидания. Одновременные запросы золота выполняются последовательно, чтобы не создавать шквал повторов. По истечении паузы следующий запрос снова проверяет основной источник. Если оба источника не дали полную историю, API возвращает HTTP 503 с причинами отказа, интерфейс очищает значения.

В API XAUUSD возвращаются `source`, `note`, `fallback`, `fallback_reason`. Эти сведения принадлежат конкретной выборке и сохраняются вместе с 30-секундным кэшем. Интерфейс показывает фактически использованный источник и причину переключения.

Проверка 11 сентября 2026 года: реальные XAUUSD получены на **1m, 5m, 15m, 1h, по 500 и 2000 закрытых свечей**. Реальный запуск с происхождением данных записывается в `live-check.json`. BTCUSDT также проверен на всех восьми сочетаниях; REST-пагинация и формулы сохранены; live-загрузка дополнительно учитывает время сервера Binance. Рассмотренный biquote в fallback не включён: фактической глубины истории недостаточно (около 300 минутных и 168 часовых свечей при проверке).

## Live-обновления

Браузер подключается к `/ws/market?symbol=BTCUSDT&timeframe=1m&limit=500`. Страница не перезагружается. Цена, OHLCV, EMA20/50, RSI, ATR, momentum и Market Analysis пересчитываются при каждом принятом рыночном событии. Объём текущей свечи заменяется накопленным объёмом источника, а не складывается повторно. При новой свече окно сохраняет выбранный размер; расчёты по незакрытой свече предварительные.

- **BTCUSDT:** публичный [Binance market-data WebSocket](https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md), `wss://data-stream.binance.vision:443/ws/btcusdt@kline_<timeframe>`, без API-ключа. История остаётся на прежнем REST-адаптере. Для live-загрузки время Binance учитывается отдельно от часов Windows. На экране показан возраст события. При отсутствии событий 10 секунд появляется отметка устаревания; при обрыве или пропуске свечи выполняются переподключение и повторная загрузка окна, без заполнения пробелов выдуманными ценами.
- **XAUUSD:** постоянная анонимная сессия OANDA через TradingView передаёт историю и последующие изменения свечи. Подключение проверено реальными событиями, но точная задержка котировки источника неизвестна: интерфейс показывает **STREAM XAUUSD · задержка источника неизвестна**, а не гарантированный realtime. При сбое/молчании потока 60 секунд включается polling примерно раз в 30 секунд; долгие ответы увеличивают интервал. Через 120 секунд работы резервного цикла повторяется попытка подключения потока. Если текущие котировки недоступны, проверяется история через цепочку Dukascopy → OANDA и явно показывается delayed-режим.

Ограничения анонимного TradingView относятся и к потоку: нет официального API-контракта и SLA, доступ может прекратиться. Во время закрытого рынка изменения не ожидаются. При переключении провайдера заменяется всё окно: BID Dukascopy и котировки OANDA не смешиваются. Одна вкладка создаёт собственное соединение источника; общий распределитель подписок пока не реализован. REST-кэш на 30 секунд не задерживает WebSocket-события.

Для проверки потока запустите приложение, затем в другом PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/check_stream.py
```

Результат — `live-stream-check.json`: реальные последовательные события BTC и XAUUSD, изменение цены/объёма, режим доставки и размер окна. 11 сентября 2026 проверка зафиксировала формирование новой минутной свечи BTC и последующие изменения текущей свечи OANDA. Отдельная проверка истории всех 16 сочетаний параметров сохраняется в `live-check.json`.

## Прозрачная модель сигнала

Индикаторы вычисляются на выбранной выборке. EMA начинается с SMA первых N свечей, далее alpha = 2/(N+1). RSI и ATR используют сглаживание Wilder с периодом 14; для первой true range используется high−low. Прогрев в начале серий исключён из линий индикаторов. RSI полностью плоской выборки равен 50. ATR=0 обрабатывается безопасно.

Обозначим `clip(x) = max(-1, min(1, x))`, `A = max(ATR14, close × 1e-10)`:

```text
E = 0.5 × clip((EMA20 − EMA50) / A)
R = 0.2 × clip((RSI14 − 50) / 25)
M = 0.3 × clip((close[t] − close[t−10]) / (3 × A))
D = 1 / max(1, std(log returns последних 20 интервалов) / std(log returns всей выборки))
UP = round(50 + 45 × (E + R + M) × D, 1)
DOWN = 100 − UP
```

При нулевой волатильности D=1. Повышенная недавняя волатильность ослабляет направленность сигнала. Это произвольная **эвристическая оценка силы сигнала**, ограниченная 5–95%, без обученной модели, бэктеста, статистической калибровки или заданного горизонта прогноза. Числа не являются вероятностями выигрыша. RSI используется как трендовый фактор, а не как правило разворота в зонах перекупленности.

Trend: `(EMA20−EMA50)/A > 0.1` → Bullish, `< −0.1` → Bearish, иначе Neutral. Доходность = `(последний close / первый close − 1) × 100`; волатильность = выборочное стандартное отклонение логарифмических доходностей × 100, **на один интервал, без годового пересчёта**. При разных интервалах значения напрямую не сопоставимы. EMA с прогревом на 500 и 2000 свечах может немного отличаться.


Тесты не требуют интернета: проверяются эталон RSI, EMA/ATR, нулевая и скачущая волатильность, границы score, декодирование BI5, агрегация, пагинация 2000 свечей, все сочетания параметров API, ошибки источников и восстановление. Реальные источники проверяются отдельно:

```powershell
.\.venv\Scripts\python.exe scripts/check_live.py
.\.venv\Scripts\python.exe scripts/check_live.py --symbol XAUUSD --output live-check.json
.\.venv\Scripts\python.exe scripts/check_live.py --gold-fallback --output gold-fallback-check.json
```

Скрипт требует интернет и запускает реальные запросы 500/2000 свечей для выбранного или обоих инструментов и всех таймфреймов, что может занять несколько минут. В отчёте — число свечей, источник, причина fallback, границы истории и цена последнего закрытия; весь набор котировок не сохраняется. Ошибка означает недоступность источника или неверный контракт, код завершения будет ненулевым. Автономные тесты дополнительно проверяют 429/503, паузу и восстановление основного источника, отсутствие смешивания источников, разбор WebSocket-пакетов и незакрытых свечей, неверный символ, отсутствие объёма и отказ обоих источников. ## Структура и расширение

```text
app/main.py          FastAPI, валидация, кэш, API и раздача frontend
app/models.py        общий контракт Candle и таймфреймы
app/providers.py     независимые адаптеры Binance / Dukascopy
app/gold.py          резервный источник OANDA через TradingView, переключение и проверка истории
app/indicators.py    чистые функции индикаторов и rule-based анализ
app/live.py          поток Binance, поток/polling XAUUSD, восстановление соединений
app/market_state.py  ограниченное live-окно, ключ серии и контракт чтения архива
static/live.js       обновление свечи и анализа без перезагрузки страницы
static/              интерфейс и локальная библиотека графика
tests/               автоматические тесты
scripts/check_live.py проверка реальных источников
start.bat            запуск на Windows
```

Historical Pattern Engine реализован отдельным пакетом `app/patterns/` с SQLite-архивом, причинными признаками, поиском аналогов и backtest. Полное описание методики, ограничений, API и запуска: [docs/PATTERN_ENGINE.md](docs/PATTERN_ENGINE.md). Старый live-график работает независимо.

Для нового источника реализуйте `Provider.fetch(client, timeframe, count)` с возвратом списка `Candle` по возрастанию UTC и добавьте экземпляр в `PROVIDERS`. Для нового индикатора добавьте чистую функцию в `indicators.py`, результат в `analyze`, затем отображение в frontend. Funding потребует отдельного источника деривативов; текущий BTC — spot. Для статистических вероятностей следующим этапом нужны фиксированный горизонт, разметка будущих доходностей, разделение train/test по времени и проверка калибровки вне обучающей выборки.
